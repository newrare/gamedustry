Games

What the motor gives every game

Only CONFIG, ASSETS and the Game module change per creative. Everything here is shared, identical code.

Portrait design space

Canvas and DOM overlays are authored in 720×1280 units and scaled as one block — no vw, no clamp(), one coordinate system.

Notch-safe layout

Layout exposes the rectangle gameplay may use: below the HUD, above the CTA bar and clear of the notch and home indicator.

Animated intro

Logo, title, one-line pitch and a CSS how-to-play demo — tap, hold, drag, swipe or aim.

HUD + overlay

Big eased score with punch animation, timer, free slots — plus toasts, combo banners, reward badges and a dramatic edge glow.

Fx juice layer

Particles, rings, floating text, screen shake, colour flash and hit-stop, wired into the frame so a game only draws its world.

Cinematic end screen

Title, score count-up with confetti, star rating, cascading stat rows, the big install CTA and a discreet replay link.

Ad-network glue

MRAID readiness, pause when not viewable, and a single Ad.openStore() for every CTA with fallbacks per network.

One round contract

A game implements reset / update / render (+ pointer hooks) and calls endRound({...}). That is the whole API.
